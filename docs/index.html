概要

NimaEngineは、DirectX12を基盤とした高性能なゲームエンジンです。コンポーネントベースのアーキテクチャを採用し、効率的なゲーム開発を実現します。

主な特徴

  • DirectX12ベースの高性能レンダリング
  • マルチスレッド対応のコマンドリスト管理
  • 柔軟なシーン管理システム
  • 充実したポストエフェクト
  • 統合されたデバッグツール（ImGui統合）
  • GLTFおよびOBJモデルのサポート
  • パーティクルシステム
  • 衝突判定システム
  • オーディオシステム（XAudio2）

アーキテクチャ

設計パターン

フレームワークパターン

すべてのアプリケーションはNimaFrameworkを継承し、Initialize()、Update()、Draw()、Finalize()をオーバーライドします。

シーンシステム

SceneBase派生クラスを使用し、SceneManagerとファクトリパターン（ISceneFactory）で管理されます。

シングルトン & 引数注入

主要システムはシングルトン（GetInstance()）として提供され、シーンへは ISceneArgs（pArgs_）を通じて必要な依存が渡されます。

オブジェクトシステム

グラフィックスオブジェクトはObjectSystemBaseMTを継承し、マルチスレッドのDirectX12コマンドリスト管理を実現します。

フレームワーク

NimaFramework

エンジンの中核となるフレームワーククラス。すべてのゲームアプリケーションはこのクラスを継承して実装します。

主要メソッド

void Run()

フレームワークのメインループを開始します。初期化、更新、描画、終了処理を順次実行します。

virtual void Initialize()

システムとサブシステムの初期化を行います。派生クラスでオーバーライドして独自の初期化処理を追加できます。

virtual void Update()

フレームごとの更新処理を行います。入力処理、シーン更新、物理演算などを実装します。

virtual void Draw()

フレームごとの描画処理を行います。レンダリングコマンドの発行と実行を管理します。

virtual void Finalize()

終了処理を行います。リソースの解放とクリーンアップを実行します。

void PreProcess()

描画前の共通前処理を行います。レンダーターゲットの設定などを実行します。

void PostProcess()

描画後の共通後処理を行います。フレーム表示とリソースのクリーンアップを実行します。

主要メンバ

DirectX12* pDirectX_

DirectX12の管理クラス

SceneManager* pSceneManager_

シーンの管理とライフサイクル制御

Input* pInput_

キーボード、マウス、ゲームパッド入力の管理

テクスチャの読み込みと管理

オーディオの再生と管理

2Dスプライトの描画システム

3Dオブジェクトの描画システム

パーティクルの描画と管理

レイヤー & Canvas

描画順序とポストエフェクトを管理するレイヤーシステムです。

Canvasを追加し、割り当てられたZ-orderを返します。後から追加したものほど手前に描画されます。

ZOrder AddCanvasTop(Canvas* canvas)

Canvasを最前面グループに追加します。

void RemoveCanvas(Canvas* canvas)

Canvasを削除します（AddCanvas したものは必ず呼び出してください）。

void ApplyPostEffects()

全Canvasにポストエフェクトを適用します。

Canvas

描画対象とポストエフェクトをまとめて管理する描画キャンバスです。

  • スプライト、3Dオブジェクト、パーティクルなどを登録

ファイルパスの正規化と解決を行います。

DIContainer (依存性注入コンテナ)

型ベースの依存性注入を行うユーティリティクラスです。※ 現時点ではエンジンのコアシステム自体はシングルトンで提供されており、DIContainerには登録されていません（コアシステムの取得には GetInstance() を使用します）。

RandomGenerator (乱数生成器)

高品質な擬似乱数を生成します。シングルトン（RandomGenerator::GetInstance()）です。

template<typename T> T Generate(T min, T max)

指定範囲の乱数を返します。型引数で整数・浮動小数点を指定できます（例: Generate<int>(0, 10)、Generate<float>(0.0f, 1.0f)）。

ThreadPool (スレッドプール)

マルチスレッド処理のためのスレッドプールを提供します。

TimeMeasurer (時間計測)

処理時間の計測とベンチマークを行います。

DeltaTimeManager (デルタタイム管理)

フレーム間の経過時間を管理します。

ConfigManager (設定管理)

ゲームの設定を読み込み、管理するシステムです。

void Initialize(const std::string& cfgPath)

設定ファイルを読み込み初期化します。シングルトン（SingletonPattern<ConfigManager>）です。

void LoadConfig(const std::string& cfgPath)

設定ファイルを読み込みます。

const cfg::ConfigData& GetConfigData() const

読み込んだ設定データを取得します。

Localization (デバッグUIラベル)

Localization 名前空間は、デバッグUI（ImGui）で使用するラベル文字列を LanguageData 構造体群として保持します。キー引きによる汎用ローカライズシステムではありません。

デバッグツール

ImGuiManager

ImGuiの統合とデバッグUIの管理を行います。

Logger

ログメッセージの記録とファイル出力を行います。

  • 階層的なログレベル（Info, Warning, Error）
  • JSON形式でのログ出力
  • タイムスタンプ付きログ

DebugManager

デバッグ機能の統合管理を行います。

EventTimer

イベントの処理時間を計測し、パフォーマンス分析を支援します。

衝突判定

auto collisionManager = CollisionManager::GetInstance();

// 形状データ（OBBの例）
OBB obb;
obb.SetCenter(Vector3(0.0f, 0.0f, 0.0f));
obb.SetSize(Vector3(0.5f, 0.5f, 0.5f));

// コライダーの作成と登録
auto collider = std::make_unique<Collider>();
collider->SetColliderID("player");
collider->SetAttribute(collisionManager->GetNewAttribute("player"));
collider->SetOwner(this); // オーナーオブジェクトへのポインタ
collider->SetShape(Shape::OBB);
collider->SetShapeData(&obb); // 形状データを設定
collider->SetMask(collisionManager->GetNewMask("player"));

// （任意）ブロードフェーズ用の球体を設定して判定を軽量化

collider->SetOnCollision([this](const Collider* other) {

    Log("Collision with: " + other->GetColliderID());
